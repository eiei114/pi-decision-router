# Pi SDK 1.2.0 compatibility

This package is verified against the frozen SDK wave: `@earendil-works/pi-agent-core`, `pi-ai`, `pi-coding-agent`, and `pi-tui` are pinned to `1.2.0` for development and tests. Public peer dependency ranges remain unchanged.

The merged [`pi-extension-template` baseline PR #131](https://github.com/eiei114/pi-extension-template/pull/131) documents the shared 1.2.0 migration findings, based on the [upstream Pi 1.2.0 release notes](https://github.com/earendil-works/pi/releases/tag/v1.2.0). The `before_agent_start` event is now a `messageType` union: `user` events carry `prompt` and `images`, while `custom` events carry `message`. This extension only reads the shared `systemPrompt` field and adds the router guidance for both event types. That is intentional: Pi 1.2.0 runs `before_agent_start` for `pi.sendMessage(..., { triggerTurn: true })`, which the router uses to resume interrupted work after automatic compaction. No deprecated API replacement is needed. The extension does not read user-only fields or call `ctx.isIdle()` / `pi.sendUserMessage()` from this handler.

The extension entrypoint, `registerTool`, shared extension event bus, TypeBox schemas, `ctx.hasUI`, and UI context lifecycle used here remain compatible. The generated configuration schema and theme changes in Pi 1.2.0 do not affect this package.

Run `npm run smoke:pi` to load the package in the actual locally pinned Pi host. `npm run ci` runs the harness. The committed result is `docs/verification/pi-sdk-smoke.json` with `verification_contract=pi-sdk-behavior-v2`. The harness verifies extension registration, the actual routed feature response, handled child-process failure, registration and feature response from a second Pi process plus clean shutdown, and the native host-shell boundary. It checks every installed SDK version against exact pins and uses an isolated temporary Pi agent directory without changing global settings.

The feature path is deterministic and offline, so no paid model inference is made. Pi's host process, extension loader, RPC handling, event adapter, fallback selection, audit write, and feature response are real rather than mocked. The error case launches a deliberately missing child executable and asserts that the router handles and audits the failure. Contract regression tests check both positive and deliberately missing responses. All smoke processes have a 15-second deadline; the shell probe launches the pinned CLI through native Windows PowerShell or `/bin/sh` on POSIX.
